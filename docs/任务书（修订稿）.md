## 二、设计（论文）的主要内容、要求及主要技术指标

### 2.1 主要内容

1. **需求分析与总体设计**：调研内容社区（内容消费 + 创作 + 管理）与智能检索相关工作，明确功能与非功能需求；完成系统架构设计、数据库设计与接口契约设计（前后台分层的 REST 接口）。
2. **前后端分离的内容社区平台实现**：前台为面向用户的**内容消费端**（信息流、频道、文章详情、点赞收藏、搜索与问答入口）；后台为**管理端**（内容、频道、用户、审核、统计），二者在入口、界面布局、接口与权限四个层面分离。
3. **用户与权限管理模块**：注册登录（JWT 鉴权）、个人信息与头像、密码修改、**角色与状态管理**（普通用户 / 管理员）、**机器作者类型**（供内容自动化使用），并保证越权访问的防护与"不存在/无权限"统一口径。
4. **内容与频道管理模块**：文章增删改查、草稿与发布状态流转、封面上传（对象存储）、共享频道维护、管理员对全站内容的可管理与审核。
5. **检索与推荐模块**：① 结构化筛选（频道/作者/时间）；② 关键词检索（标题与摘要，返回命中片段）；③ 基于用户行为画像的推荐重排（行为埋点 → 频道兴趣权重 → 排序公式）；④ 冷启动与多样性控制。
6. **AI 智能检索与问答模块**：以**大语言模型智能体**为核心，通过**只读工具调用**检索社区文章与用户画像，返回"回答 + 引用文章"，引用须由服务端从工具真实结果拼装（不采信模型复述的编号），并对草稿等不可见内容做强制隔离。
7. **检索日志与统计模块**：记录浏览/搜索/问答日志（含耗时与结果数），提供后台统计看板（热门查询、无结果率、点击率、响应耗时分布），为实验分析提供数据支撑。
8. **测试与评测**：构建**公开数据集**离线评测集与线上埋点两套实验方案，从准确性、多样性、覆盖率、响应耗时与业务指标五个维度对比基线方法与本文方法。
9. **（扩展）内容自动化**：接入合规外部内容源（官方 API / RSS），以"**摘要 + 来源署名 + 原文链接**"的方式产出草稿，保留人工审核闸门与一键停止开关。

### 2.2 设计要求

1. 系统采用前后端分离架构，接口遵循统一的响应结构与错误码约定；前端至少完成**消费端与管理端两套界面**。
2. 数据库设计需给出 ER 图与建表脚本，包含索引与约束设计（含软删除与幂等约束）；关键写操作需考虑事务与并发安全。
3. 代码遵循分层规范（Controller / Service / Mapper），提供必要的单元测试；仓库使用 Git 管理，提交信息规范。
4. **数据来源以公开数据集为主、合规采集为辅**，不得依赖未授权爬虫；线上内容一律采用"摘要 + 链接"模式，不全文搬运，并标注来源。
5. 论文需给出完整的需求分析、系统设计、实现、测试与评测章节；实验部分须有可复现的数据集说明、参数设置与结果分析。
6. 参考文献以**近 5 年期刊文献**为主，数量与格式按学院要求。

### 2.3 主要技术指标

> ⚠️ 下列阈值是**建议目标值**，请在实验后按实测结果回填（写"达到/不低于 X"时须有实验数据支撑）。

| 类别 | 指标 | 建议目标 |
|---|---|---|
| 准确性 | Precision@10、nDCG@10（离线评测集） | 相对时间序基线提升 ⚠️（以实测为准） |
| 多样性 | 列表内相似度 ILS、类别分布熵 | ILS 低于热度基线 ⚠️ |
| 覆盖率 | 物品覆盖率（推荐到的文章占全库比例） | ≥ ⚠️%（建议 50%~80%） |
| 性能 | 列表/搜索接口 P95 响应耗时 | ≤ 500 ms ⚠️（不含大模型调用） |
| 性能 | AI 问答首字延迟（TTFT）/ 端到端耗时 | TTFT ≤ 3 s、端到端 ≤ 15 s ⚠️ |
| 并发 | 支持并发用户数 | ≥ ⚠️（建议 50 并发压测） |
| 业务 | 搜索无结果率、AI 引用命中率、点击率 | 无结果率 ≤ ⚠️%；引用命中率 = 100%（引用必为真实文章） |
| 功能 | 必须完成的核心模块 | 2.1 的 1~8 项全部完成 |
