# 推荐与用户画像说明

## 1. 功能边界

当前实现为**基于用户行为的规则画像与推荐重排**，不调用大语言模型，也不声称使用了协同过滤或深度学习。浏览、点赞和收藏形成频道级行为信号；规则画像影响「为你推荐」信息流。用户没有画像或行为样本不足时，系统回退到最新发布顺序。

```text
文章曝光 / 阅读停留 / 点赞 / 收藏
              ↓
       browse_log / user_action
              ↓
       近 7 天规则画像
              ↓
最新 100 篇已发布候选 → 规则打分重排 → 返回最多 30 篇
```

## 2. 画像生成

每日定时任务为近 7 天有浏览行为的用户重新计算画像。画像按频道合并浏览量、平均停留时长、点赞与收藏数，原始频道分数为：

```text
raw(category) = pv + 3 × actions + 2 × (avgDwellMs / 30000)
weight(category) = raw(category) / Σ raw(all categories)
```

画像保存于 `user_profile` 和 `user_profile_interest`。`sample_size` 用于判断画像是否具有足够的行为样本；推荐侧将样本数小于 3 的画像视为冷启动，回退到时间排序。

## 3. 推荐候选与排序

推荐模式查询最新 100 篇已发布文章，列表 SQL 不读取富文本正文。排序公式为：

```text
score(article) = (categoryWeight + 0.02)
                 × 2 ^ (-ageHours / (24 × 7))
                 × (1 + ln(1 + viewCount))
                 × freshnessBoost
```

- `categoryWeight`：用户画像中的频道权重；无匹配频道时取 0。
- `0.02`：给画像未覆盖的频道保留少量探索机会。
- 时间衰减半衰期为 7 天；24 小时内的新文章额外乘以 `1.5`，避免新内容没有初始曝光。
- 同分时按创建时间、文章 ID 倒序，保证排序稳定。

这些参数是可解释的初始启发式，不是训练得到的模型参数；后续应依据离线评估调整。

## 4. 接口与分页约定

```text
GET /article/list?mode=latest&pageNum=1&pageSize=8&state=已发布
GET /article/list?mode=recommend&state=已发布
```

- `latest` 是默认模式，使用普通分页和瀑布流无限加载。
- `recommend` 只返回已发布文章，候选先重排再返回最多 30 篇；深翻页参数不用于获取额外推荐结果。
- 不能在数据库分页后才重排，否则较高分内容可能落到后续页，并导致推荐页出现漏项或重复。
- 浏览埋点记录 `mode`，便于分别统计推荐与最新模式下的曝光和停留。旧客户端未传该字段时按 `latest` 记录。

## 5. 离线评估方案

个人项目样本量较小时，建议使用可复现的离线留出评估，而不是声称完成线上 A/B 测试：

1. 按用户和时间排序行为记录，用前 5 天行为生成画像，保留第 6–7 天的阅读作为测试目标。
2. 对同一候选集合分别运行画像重排和按时间倒序基线。
3. 计算 `Recall@K`、`NDCG@K`，同时记录有效用户数、正反馈数量和响应时间。
4. 汇报冷启动用户的回退表现；如果有效样本不足，应如实说明数据不足以支持稳定结论。

浏览记录的 `mode` 数据库变更见 `sql/migration/002_browse_log_mode.sql`。执行迁移前先备份数据库；已有数据库不要重新运行会删除表的初始化脚本。
