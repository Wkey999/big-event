# Redis 会话退出：本地实现与启用边界

当前代码已接入 Redis JWT 撤销名单，尚未在真实 Redis 上联调，也未部署到云端。默认 `AUTH_TOKEN_REVOCATION_ENABLED=false`，现有站点行为不会因为缺少 Redis 而变化。

## 为什么选这个场景

原先前端退出只删除浏览器的 JWT；若令牌已泄露，签名和有效期仍成立，后端在过期前会继续接受。现在显式退出调用 `POST /user/logout`，后端仅把令牌 SHA-256 摘要写入 Redis，TTL 等于该 JWT 的剩余有效期。鉴权时先验签，再检查摘要是否存在；存在则返回 401。新签发的 JWT 包含随机 `jti`，同一用户连续登录不会意外共用完全相同的令牌。Redis 中不保存原始 JWT。

这是**当前令牌退出**，不是单设备登录，也不是修改密码后撤销所有设备的令牌。AI 免费次数和点赞计数仍由 MySQL 保证事务一致性。

## 本地启用与验证

1. 在本机启动可用的 Redis，限定为 `127.0.0.1:6379`；不要把 6379 暴露到公网。若设置了密码，开发环境通过 Spring Boot 的 `SPRING_DATA_REDIS_PASSWORD` 环境变量提供。
2. 启动后端前设置 `AUTH_TOKEN_REVOCATION_ENABLED=true`，然后按 README 的方式启动 Java 服务。前端仍使用 `/api` 代理。
3. 登录并保存测试令牌；用该令牌访问 `GET /api/user/userInfo` 应成功。点击网站“退出登录”后，用**同一个旧令牌**再次访问应返回 401；重新登录得到的新令牌应可正常访问。只在本机测试，不把真实令牌写入文档、聊天或日志。
4. 停掉 Redis 再发受保护请求，应得到 503，不应把不可用误判为“未登录”或允许旧令牌访问。恢复 Redis 后再验证。需要保留已撤销记录跨重启时，Redis 应开启 AOF 持久化；否则 Redis 重启清空内存可能让尚未过期的旧令牌重新有效。

生产配置项在 `application-prod.yml`：`REDIS_HOST` 默认 `127.0.0.1`、`REDIS_PORT` 默认 `6379`、可选 `REDIS_PASSWORD`。先安装并验证本机 Redis、限制监听地址、启用持久化，再把 `AUTH_TOKEN_REVOCATION_ENABLED=true` 写入服务器私有环境文件并重启 Java 服务。生产启用后每个受保护请求都会查询 Redis；Redis 故障时鉴权返回 503，显式退出写入失败时前端保留当前登录状态并显示错误。切换前需安排健康检查与故障处理。

自动测试覆盖摘要、TTL、关闭模式、已撤销令牌拒绝及 Redis 查询失败；不等同于真实 Redis 联调。云端实例与公网 IP 每次部署前都应重新核对，本页不记录固定地址。
