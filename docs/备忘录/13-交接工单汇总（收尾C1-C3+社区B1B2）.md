## 1. 阶段 1：收尾修复（小、必须先做）

### 1.1 C1 —— 404 语义（最重要）

**现状问题**（实测）：带合法 token 请求不存在的路径
```
GET /no/such/path    -> [HTTP 200] {"code":1,"message":"服务器内部错误","data":null}
GET /article/nosuch  -> [HTTP 200] {"code":1,"message":"服务器内部错误","data":null}
```
原因：`config/GlobalExceptionHandler` 的兜底 `@ExceptionHandler(Exception.class)` 把
`NoResourceFoundException`（Spring Boot 3.2+ 未匹配路径异常）也接住了。

**要求**
- 在 `GlobalExceptionHandler` 中**单独**处理 `NoResourceFoundException` 与 `NoHandlerFoundException`：
  返回 **HTTP 404** + `{"code":404,"message":"接口不存在","data":null}`
- **不得回归**：已存在路由的**业务错误**仍是 **HTTP 200 + `code≠0`**（参数校验失败、"智能问答未启用" 等）
- 未登录访问不存在路径：仍由 `JwtInterceptor` 先返回 **401**（拦截器优先，保持现状）
- 补测试：① 已登录访问不存在路径 → 404 + `code=404`；② 参数校验失败仍为 200 + `code≠0`

### 1.2 C2 —— `ArticleAskController` 清理

- 删除**重复 import**：`org.springframework.beans.factory.ObjectProvider` 出现两次（第 12、17 行）
- 修正**过时类注释**：现注释写 "Only available when a local LLM configuration explicitly enables the Agent"，
  但控制器现在**始终注册**、靠 `ObjectProvider` 判空兜底 → 注释改为描述真实行为
- **不要改兜底逻辑**：`getIfAvailable() == null` → 写一条 `success=0` 的 `ask_log` + 抛
  `BusinessException("智能问答未启用")`；该行为已验证通过

## 2. 阶段 2：B1 —— 帖子媒体 + 话题

### 2.1 迁移 `sql/migration/005_community_core.sql`（幂等，本批建 3 张表；B2 的 2 张表可同文件一次建完）

```sql
CREATE TABLE IF NOT EXISTS `post_media` (
  `id`          bigint unsigned NOT NULL AUTO_INCREMENT,
  `article_id`  bigint unsigned NOT NULL,
  `url`         varchar(255)    NOT NULL,
  `media_type`  tinyint         NOT NULL DEFAULT 1 COMMENT '1-图片 2-视频',
  `sort_order`  int             NOT NULL DEFAULT 0,
  `width`       int                      DEFAULT NULL,
  `height`      int                      DEFAULT NULL,
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_article` (`article_id`, `sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='帖子媒体';

CREATE TABLE IF NOT EXISTS `topic` (
  `id`          bigint unsigned NOT NULL AUTO_INCREMENT,
  `name`        varchar(30)     NOT NULL,
  `post_count`  int unsigned    NOT NULL DEFAULT 0 COMMENT '冗余计数',
  `hot_score`   int unsigned    NOT NULL DEFAULT 0 COMMENT '热度分，可定时刷新',
  `status`      tinyint         NOT NULL DEFAULT 1 COMMENT '0-隐藏 1-正常',
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE INDEX `uk_name` (`name`),
  INDEX `idx_hot` (`status`, `hot_score` DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='话题';

CREATE TABLE IF NOT EXISTS `post_topic` (
  `article_id`  bigint unsigned NOT NULL,
  `topic_id`    bigint unsigned NOT NULL,
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`article_id`, `topic_id`),
  INDEX `idx_topic` (`topic_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='帖子话题关系';
```

### 2.2 接口

| 方法 | 路径 | 请求 | 响应/说明 |
|---|---|---|---|
| GET | `/article/{id}/media` | — | `[{id,url,mediaType,sortOrder,width,height}]` 按 `sort_order,id` 升序；**任何人可读**（草稿帖仅作者/管理员） |
| PUT | `/article/{id}/media` | `{"media":[{"url":"","mediaType":1,"width":0,"height":0}]}` | 全量替换；**第一条 URL 同步写入 `article.cover_img`**；仅作者或管理员 |
| GET | `/topic/list?sort=hot\|new&limit=20` | — | `[{id,name,postCount}]`；`hot` 按 `hot_score DESC, post_count DESC, id DESC`；`new` 按 `create_time DESC`；仅 `status=1` |
| GET | `/topic/{id}/posts?pageNum&pageSize` | — | 该话题下**已发布**帖子分页（复用现有列表字段，**不含 `content`**） |

### 2.3 扩展既有发帖/改帖（**不传新字段时行为必须与现在完全一致**）

- `POST /article/add`、`PUT /article/update` 接受可选 `media[]` 与 `topicNames[]`
- `topicNames`：去首尾空白、长度 ≤30、**一帖最多 5 个**（超出报业务错误）；存在则复用，不存在则创建
- 帖子软删时：清理 `post_topic` 关联并回退 `topic.post_count`

### 2.4 实现要点

1. `topic.post_count` 必须与 `post_topic` 行数一致（同事务维护）
2. 媒体全量替换用"差异更新"或"先删后插"，但**必须保证首图与 `cover_img` 同步**
3. 话题热度 `hot_score` 本批**可以先不刷新**（留空/0），但字段与排序要预留

## 3. 阶段 3：B2 —— 评论 + 关注

### 3.1 表（同上迁移文件）

```sql
CREATE TABLE IF NOT EXISTS `comment` (
  `id`          bigint unsigned NOT NULL AUTO_INCREMENT,
  `article_id`  bigint unsigned NOT NULL,
  `user_id`     bigint unsigned NOT NULL,
  `root_id`     bigint unsigned          DEFAULT NULL COMMENT '楼层根评论 id，顶层为 NULL',
  `parent_id`   bigint unsigned          DEFAULT NULL COMMENT '被回复的评论 id',
  `content`     varchar(500)    NOT NULL,
  `like_count`  int unsigned    NOT NULL DEFAULT 0,
  `reply_count` int unsigned    NOT NULL DEFAULT 0,
  `state`       tinyint         NOT NULL DEFAULT 1 COMMENT '0-隐藏 1-正常',
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `deleted`     tinyint         NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  INDEX `idx_article_time` (`article_id`, `deleted`, `create_time`),
  INDEX `idx_root` (`root_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='评论';

CREATE TABLE IF NOT EXISTS `user_follow` (
  `id`          bigint unsigned NOT NULL AUTO_INCREMENT,
  `follower_id` bigint unsigned NOT NULL COMMENT '关注者',
  `followee_id` bigint unsigned NOT NULL COMMENT '被关注者',
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE INDEX `uk_follow` (`follower_id`, `followee_id`),
  INDEX `idx_followee` (`followee_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='关注关系';
```

### 3.2 接口

| 方法 | 路径 | 请求 | 说明 |
|---|---|---|---|
| GET | `/article/{id}/comments?pageNum&pageSize` | — | **只分页顶层评论**（`root_id IS NULL`、`deleted=0`）；每层返回 `replyCount` + 前 2 条回复；按 `create_time DESC, id DESC` |
| GET | `/comment/{rootId}/replies?pageNum&pageSize` | — | 该楼层全部回复，`create_time ASC, id ASC` |
| POST | `/article/{id}/comment` | `{"content":"","rootId":null,"parentId":null}` | 内容非空且 ≤500 字；返回新评论对象 |
| DELETE | `/comment/{id}` | — | 仅**作者或管理员**；软删（`deleted=1`） |
| POST / DELETE | `/comment/{id}/like` | — | 幂等；复用 `user_action`（`target_type=2`, `action_type=1`） |
| POST / DELETE | `/follow/{userId}` | — | 幂等；**不能关注自己**；返回 `{followed,followerCount,followeeCount}` |
| GET | `/user/{id}/follow` | — | `{followed,followerCount,followeeCount}` |

**评论分页响应结构（前端契约，务必按此形状）**
```json
{ "code":0, "message":"success", "data":{ "total":12, "items":[
  { "id":101, "userId":4, "nickname":"张三", "avatar":"",
    "content":"…", "likeCount":3, "liked":false, "replyCount":2,
    "createTime":"2026-10-13 20:00:00",
    "replies":[ { "id":105, "parentId":101, "content":"…", "nickname":"李四", "likeCount":0, "liked":false, "createTime":"…" } ] } ] } }
```

### 3.3 实现要点

1. **两级结构**：顶层 `root_id = NULL`；回复必须带 `rootId`，且该 root 必须属于**同一帖**（否则报业务错误）；`parentId` 可选
2. **计数一致性（同事务）**：
   - `article.comment_count` = 该帖**未删除**评论总数（含回复）
   - `comment.reply_count` = 该楼层**未删除**回复数（只在 root 上累加）
   - `comment.like_count` = `user_action(target_type=2, action_type=1)` 行数
3. **可见性/权限**：草稿帖（`state=0`）**不可评论**；未登录不可写；隐藏/软删评论不下发也不计数
4. **幂等**：重复关注/取关、重复点赞/取消点赞，计数**不得漂移**（唯一键 + `DuplicateKeyException` 兜底，或 `INSERT ... ON DUPLICATE KEY UPDATE`）
5. `liked` 字段：当前登录用户是否已点赞（未登录返回 `false`）
