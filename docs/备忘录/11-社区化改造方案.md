# 备忘录 11：社区化改造方案（借鉴得物社区的信息架构）

> 需求方决策（2026-10-13）：前端**彻底重构**，主要借鉴对象是**得物社区**（`dewu.com/community` / 得物 App 首页社区）。
> 公开来源：[得物技术博客 · 走进社区客户端测试](https://tech.dewu.com/article?id=44)、[得物 App 产品分析报告](https://www.woshipm.com/evaluating/5391729.html)。
> 本文只做**信息架构与交互模式的借鉴**，不涉及任何源码/二进制分析，不复制对方素材。

## 0. 借鉴边界（答辩时按这个说）

| 做 | 不做 |
|---|---|
| 借鉴信息架构：双流（关注/推荐）、圈子/频道、话题、双列卡片流、详情页结构 | 复制素材：图片、图标、文案、字体文件 |
| 借鉴交互模式：卡片内快速点赞、图集轮播、底部悬浮互动栏、发布流程 | 反编译 / 抓接口 / 绕过风控 / 分析其客户端代码 |

论文措辞：**「基于公开资料的竞品信息架构与交互模式借鉴」**（附公开来源），不写"逆向/拆解源码"。

## 1. 得物社区的可观察结构（公开资料摘要）

| 层 | 观察到的结构 |
|---|---|
| 首页（社区） | 顶栏按**大类**切换，默认**推荐**；下方是垂直细分的**圈子**（默认"全部"）；内容为**双列"图封面 + 标题"卡片**；**卡片右下角可直接点赞** |
| 内容形态 | 图文/视频**动态**；发布时可挂**热度话题**；动态可关联商品（内容带货） |
| 互动 | 点赞（卡片上即可点）、评论、关注达人 |
| 创作者侧 | 创作中心（数据中心 / 成长任务 / 创作灵感 / 创作者学院） |
| 其他 | 鉴别社区、直播、话题活动、榜单 |

## 2. 现状差距（后端先行清单的依据）

> 口径更正（需求方）：**现有 `article` 就是帖子**（不是"文章 CMS 要换成帖子"）。列表用 `cover_img` 当封面、正文放 `content`，发帖/浏览/点赞收藏都已可用。
> 所以要做的不是"换模型"，而是**补齐社区能力**：多图、话题、评论、关注、关注流、主页聚合。

| 能力 | 本项目现状 | 社区化需要 | 后端动作 |
|---|---|---|---|
| 内容载体 | `article`：单封面 `cover_img` + 富文本 `content` | 帖子支持**多图/视频** | 新增 `post_media`（1:N，`cover_img` 仍是列表首图，不改现有查询） |
| 分类 | `category` 频道（管理员维护） | 频道 ≈ **圈子**（保留）+ **话题**（用户可参与、有热度） | 新增 `topic` + `post_topic` |
| 评论 | 仅 `article.comment_count` 字段，**无评论功能** | 评论 + 回复（楼层） | 新增 `comment` |
| 关注 | ❌ 无 | 关注关系 + 关注流 | 新增 `user_follow` |
| 信息流 | 单流（`/article/list` 的 `latest`/`recommend`） | **双流：关注 / 推荐** | 复用 recommend，新增 `following` 流 |
| 个人主页 | 仅 `/user/userInfo` | 主页：作品/喜欢/收藏 + 粉丝/关注数 | 新增聚合接口 |
| 互动 | 赞/藏 ✓ 幂等 + 冗余计数 | + 评论点赞、分享、举报 | 扩 `user_action`（现有 `target_type` 天然支持 1=帖子、2=评论） |
| 通知 | ❌ 无 | 赞/评/关注通知 | 新增 `notification`（可选，扩展） |

> ✅ 复用优势：`user_action(user_id,target_id,target_type,action_type)` 的唯一键设计与 `browse_log` 埋点**可直接支撑**社区互动与推荐，无需推翻。

## 3. 数据模型（新增表 DDL 草案）

```sql
-- 帖子媒体（多图/视频）；首图沿用 article.cover_img 作为列表封面，避免改动列表查询
CREATE TABLE `post_media` (
  `id`         bigint unsigned NOT NULL AUTO_INCREMENT,
  `article_id` bigint unsigned NOT NULL,
  `url`        varchar(255)    NOT NULL,
  `media_type` tinyint         NOT NULL DEFAULT 1 COMMENT '1-图片 2-视频',
  `sort_order` int             NOT NULL DEFAULT 0,
  `width`      int                      DEFAULT NULL,
  `height`     int                      DEFAULT NULL,
  `create_time` datetime       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_article` (`article_id`, `sort_order`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='帖子媒体';

-- 话题
CREATE TABLE `topic` (
  `id`         bigint unsigned NOT NULL AUTO_INCREMENT,
  `name`       varchar(30)     NOT NULL,
  `post_count` int unsigned    NOT NULL DEFAULT 0 COMMENT '冗余计数',
  `hot_score`  int unsigned    NOT NULL DEFAULT 0 COMMENT '热度分，定时刷新',
  `status`     tinyint         NOT NULL DEFAULT 1 COMMENT '0-隐藏 1-正常',
  `create_time` datetime       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE INDEX `uk_name` (`name`),
  INDEX `idx_hot` (`status`, `hot_score` DESC)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='话题';

-- 帖子-话题 多对多（一帖最多 5 个话题由服务层限制）
CREATE TABLE `post_topic` (
  `article_id` bigint unsigned NOT NULL,
  `topic_id`   bigint unsigned NOT NULL,
  `create_time` datetime       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`article_id`, `topic_id`),
  INDEX `idx_topic` (`topic_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='帖子话题关系';

-- 评论（两级：root 楼层 + 楼层内回复，避免无限嵌套）
CREATE TABLE `comment` (
  `id`          bigint unsigned NOT NULL AUTO_INCREMENT,
  `article_id`  bigint unsigned NOT NULL,
  `user_id`     bigint unsigned NOT NULL,
  `root_id`     bigint unsigned          DEFAULT NULL COMMENT '楼层根评论 id，顶层为 NULL',
  `parent_id`   bigint unsigned          DEFAULT NULL COMMENT '被回复的评论 id',
  `content`     varchar(500)    NOT NULL,
  `like_count`  int unsigned    NOT NULL DEFAULT 0,
  `reply_count` int unsigned    NOT NULL DEFAULT 0,
  `state`       tinyint         NOT NULL DEFAULT 1 COMMENT '0-隐藏 1-正常',
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `deleted`     tinyint         NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  INDEX `idx_article_time` (`article_id`, `deleted`, `create_time`),
  INDEX `idx_root` (`root_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='评论';

-- 关注关系
CREATE TABLE `user_follow` (
  `id`          bigint unsigned NOT NULL AUTO_INCREMENT,
  `follower_id` bigint unsigned NOT NULL COMMENT '关注者',
  `followee_id` bigint unsigned NOT NULL COMMENT '被关注者',
  `create_time` datetime        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE INDEX `uk_follow` (`follower_id`, `followee_id`),
  INDEX `idx_followee` (`followee_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='关注关系';
```

迁移文件：`sql/migration/005_community_core.sql`（幂等，沿用 003 的 `information_schema` + `PREPARE/EXECUTE` 写法）；同步更新 `sql/big_event_init.sql`。

## 4. 接口契约（新增/扩展）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/feed?mode=following\|recommend\|latest&cursor=` | 统一信息流入口；`following` 走关注关系，`recommend` 复用现有重排 |
| GET | `/article/{id}/detail`（扩展） | 详情额外返回 `media[]`、`topics[]`、`author{id,nickname,avatar,followed}` |
| GET | `/article/{id}/comments?pageNum&pageSize` | 楼层分页；每层带前 2 条回复 + `replyCount` |
| POST | `/article/{id}/comment` | body `{content, rootId?, parentId?}`；返回新评论 |
| DELETE | `/comment/{id}` | 仅作者或管理员；软删 |
| POST | `/comment/{id}/like` / `DELETE` | 复用 `user_action`（`target_type=2`），幂等 + 冗余计数 |
| POST | `/follow/{userId}` / `DELETE` | 关注/取关，幂等；返回双方计数 |
| GET | `/topic/list?sort=hot\|new` | 话题列表（横滑栏用） |
| GET | `/topic/{id}/posts` | 话题下帖子流 |
| GET | `/user/{id}/profile` | 主页聚合：基本信息 + 作品/喜欢/收藏数 + 粉丝/关注数 + `followed` |
| GET | `/user/{id}/posts?tab=works\|likes\|collects` | 主页三个 Tab |
| PUT | `/article/update`（扩展） | 支持提交 `mediaIds` 顺序与 `topicNames[]` |

统一约定沿用现有：响应 `{code,message,data}`；列表**永不返回 `content`**；分页参数夹取；业务错误 HTTP 200 + `code≠0`（**404 语义按备忘录 09 F1 修**）。

## 5. 前端页面与组件（**桌面优先 PC Web**）

> 口径更正（需求方）：本项目是 **PC Web**，不做移动优先。得物社区是移动 App，**只借鉴信息架构与交互模式，布局按桌面重设计**（多列、侧栏、左右分栏）。

**页面**：
- `FeedView`：顶部导航 + **左侧频道(圈子)栏** + 主区信息流；顶部 Tab「关注 / 推荐 / 最新」
- `TopicView`：话题头部（名称 + 帖子数 + 关注）+ 话题下帖子流
- `PostDetailView`：**左右分栏** —— 左：图集/正文/话题 chips；右：作者卡（关注按钮）+ 互动栏 + 评论区
- `PublishView`：多图上传 + 正文编辑器 + 话题选择
- `UserProfileView`：头部（头像/简介/关注·粉丝·作品数）+ Tab（作品/喜欢/收藏）
- 管理端：沿用 `/admin`（后续做界面）

**组件**：`FeedMasonry`（桌面 3~4 列瀑布流/网格，列数随宽度自适应）、`PostCard`（封面 + 标题 + 作者 + 点赞）、`MediaCarousel`（详情页图集）、`TopicChip`、`CommentList` / `CommentItem` / `CommentComposer`、`FollowButton`、`ActionBar`（赞/藏/评/分享）、`ChannelSidebar`、`EmptyState` / `Skeleton` / `ErrorState`

**响应式**：桌面为主（≥1280px 为设计基准），≤1024px 降为单列属于"基本适配"，**不作为设计目标**。

**必须保留的既有逻辑**（抽成 composables 后再重构）：`useFeedPagination`（防串流 `feedRequestVersion` + id 去重）、`useExposureTracking`（曝光去抖 + mode 归因）、`useArticleEngagement`（乐观更新 + 幂等）、`useArticlePreview`（停留计时）、`useRichText`（DOMPurify 白名单）。

## 6. 毕设范围控制

**做这 5 个闭环**：
1. 发布：多图 + 正文 + 话题
2. 浏览：双流（关注/推荐）+ 圈子 + 话题页
3. 详情：图集 + 正文 + 评论（含回复）
4. 互动：赞/藏/评/关注（复用幂等计数）
5. 主页：作品/喜欢/收藏 + 粉丝关注数

**不做（列为扩展）**：直播、商品带货、鉴别服务、私信、抽签/活动、创作者激励体系、通知中心（可选做）。
