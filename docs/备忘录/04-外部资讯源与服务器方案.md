## 1. 源清单（按现有频道）

接入优先级：**官方 API > 官方 RSS > RSSHub 生成 > 爬虫（尽量避免）**

| 频道 | 源 | 接入方式 | 许可/风险 | 需要 RSSHub? | 自带图 |
|---|---|---|---|---|---|
| AI热点 | Hacker News（官方） | REST API | 开放 | ❌ | 无 → 自产 |
| AI热点 | arXiv（官方） | Atom API | 开放 | ❌ | 无 → 自产 |
| AI热点 | GitHub Trending | API/页面 | 开放（有速率限制） | 可选 | 有头像 |
| AI热点 | 量子位 / 机器之心 / InfoQ | RSSHub 路由 | 源站版权 → **摘要+链接** | ✅ | 有 |

**建议首批（零抓取风险、不需要常驻服务）**：HN API + arXiv API + GitHub Trending + 1 个中文科技源（经 RSSHub）。

## 2. 采集架构（本地即可跑通）

```
Spring Boot @EnableScheduling 采集任务（复用 task/ProfileRefreshTask 范式）
   → 源适配器（rss / api）
   → 去重（source_url 唯一索引 + 标题相似度）
   → LLM 摘要（只摘要源文已有事实，禁止生成无来源断言）
   → 封面（若选 D：模板生成 → 上传 OSS）
   → 落库为草稿 state=0
   → 【可选】人工审核 → 发布 state=1
```

- 审计：`fetch_log`（http_code / err / batch_id）+ `content_source`（源配置、启用开关、周期、last_fetch_at）
- **kill switch**：`app.bot.enabled=false` 一键停止采集与产出
- 频道路由与作者绑定：一个 AI 助手 = 一组源 = 一个频道（见备忘录 03）

## 3. 服务器策略（本次核心问题）

### 3.1 先把两件事分开

| 事情 | 负载特征 | 能否不租服务器 |
|---|---|---|
| **采集**（定时抓取 + 摘要 + 存草稿） | 轻，几十秒一次 | ✅ 本地 / 甚至 GitHub Actions 定时任务都能做 |
| **网站 7×24 在线**（别人随时能访问） | 重，必须常驻 | ❌ 必须服务器或托管 |

所以真正的决策不是"要不要为 RSSHub 租服务器"，而是：**你的网站需要一直在线吗？**

### 3.2 三档方案

| 档 | 方案 | 成本 | 适用于 | 限制 |
|---|---|---|---|---|
| 0 | 本机跑（官方 API 直连；需要 RSSHub 时用本地 Docker） | **¥0** | 开发、毕设调试、录屏演示 | 关机即停；外网访问需穿透 |
| 1 | 本机 + 公网穿透（cpolar / frp / ngrok） | ¥0~低 | 临时给老师/同学演示 | 不稳定，需保持开机 |
| 2 | 轻量云服务器（Docker Compose：app + MySQL + RSSHub + Nginx） | 国内 2C2G 学生/新用户 ≈ **¥60~100/年**或 ¥50~70/月；海外 VPS $5~6/月 | 7×24 在线、自动采集、可绑域名 | 国内**绑域名需备案**（1~2 周）；2C2G 内存吃紧 |

### 3.3 若上服务器，部署要点

- **限内存**：JVM `-Xmx512m`；MySQL `innodb_buffer_pool_size` 调小；RSSHub 2C2G 同机会紧张 → 建议 **2C4G** 或 RSSHub 单独部署
- **配置外置（项目已改造完成）**：根目录 `application-secret.yml` / `application-oss.yml` / `application-llm.yml` + 环境变量注入，天生适配容器部署
- **安全**：安全组只开必要端口；MySQL **不要暴露公网**；SSH 用密钥登录
- **备份**：MySQL 定时 `mysqldump` + 保留 N 份
- **备案**：国内服务器绑域名必须备案（提前 1~2 周启动）；想免备案选香港/新加坡轻量

### 3.4 建议（分阶段，不花冤枉钱）

1. **现在：不租。** 用官方 API（HN / arXiv / GitHub / Riot）在本地跑通"采集 → 摘要 → 草稿 → 封面 → 发布"闭环——**这个阶段完全不需要 RSSHub 常驻**，也就不需要服务器。
2. **需要更多中文源时**：本地 Docker 起 RSSHub；可先用其公共实例验证路由可用性，再自建。
3. **要长期在线 / 答辩演示前**：租**国内轻量 2C2G 起**（有学生优惠），Docker Compose 一键起；要绑域名就提前办备案。
4. **只想"每天自动更新内容"但不想养服务器**：可用 **GitHub Actions 定时任务**跑采集（免费额度），但注意它**只能产出内容，不能替代"网站常驻"**；且后端需公网可达或改为把结果提交回仓库。

## 4. 数据模型（与现有代码对齐）

- `article` 增列：`source_url`（**唯一索引，天然幂等去重**）、`source_name`、`source_type`(rss/api/manual)、`source_published_at`、`cover_origin`(generated/original/none)、`generated_by`(AI 作者 user_id)
- 新增 `content_source`：`id, name, type(rss/api), url, channel_id, bot_user_id, enabled, fetch_interval, last_fetch_at, create_time`
- 新增 `fetch_log`：`id, source_id, batch_id, url_hash, status, http_code, err, create_time`
- 后台管理入口挂在 `/admin/content-source/**`（见备忘录 01）

## 5. 验收标准

1. **单源闭环**：按周期自动新增**去重**草稿；每条含**摘要 + 原文链接（必填）**；封面若选 D 则全部自产
2. **可观测**：`fetch_log` 能看到每次采集的 http_code 与错误；kill switch 立即生效
3. **合规**：无全文搬运；每条都有来源署名与原文链接
4. **部署（若上服务器）**：机器重启后 app / MySQL / RSSHub 自动拉起；备份可恢复
