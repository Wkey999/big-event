# 备忘录 10：数据基础（第一批：演示种子数据）

> 需求方决策（2026-10-13）：**先做演示数据**让站点与统计看板"有血有肉"；**论文评测数据集后置**。
> 定位：本项目最终要做"**机器人每日自动发布最新内容**"，所以演示数据只是第一步，真正的"新鲜内容"要靠后续的内容源接入。

## 0. 决策记录

| 项 | 决策 |
|---|---|
| 本批目标 | **演示种子数据**（不是评测集） |
| 评测数据集 | **后置**；届时用 **MIND**（英文新闻 + 曝光点击日志，最适合推荐/检索评测） |
| 知乎 / Reddit | **不作为内容源**——两者公开数据基本是归档的旧文，只能拿旧文章，"没什么意思" |
| 内容自动化方向 | 后续接入 **MIND + GitHub 等新鲜源**，让机器人每日产出；需要新增 `source_url` 去重列（留待后续迁移） |
| 规模 | **30 用户 / 5 频道 / 100 文章 / 1000 行为** |
| 脚本位置 | `tools/data/`（独立目录，**不侵入后端代码**），由 DSH 编写 |
| 执行方式 | 单文件 Java + 本地 JDBC 驱动（无需给 Python 装 MySQL 驱动） |

## 1. 数据设计

| 对象 | 设计 |
|---|---|
| 用户 30 个 | `demo_user_01..30`，中文昵称、邮箱；`role=0`；密码统一复用现有 BCrypt 哈希（等价于 `123456`，**演示用途，文档标注**） |
| 机器作者 5 个 | `bot_ai / bot_sports / bot_esports / bot_tech / bot_finance`，`user_type=1`（第一批迁移已加该列），对应 5 个频道 |
| 频道 5 个 | **复用现有** `AI热点(32) / 体育(38) / 电竞(35) / 科技数码(39) / 财经商业(40)`，不新建 |
| 文章 100 篇 | 中文标题（≤40 字，列上限 100）、摘要（≤120 字，列上限 500）、正文 3~5 段 `<p>`；约 **90 篇已发布 + 10 篇草稿**（让后台草稿视图也有内容）；`create_time` 分布在近 60 天，**含近 24 小时若干**（时间窗演示可用）；封面复用库中已有的 OSS 图循环分配 |
| 行为约 1000 行 | `browse_log` 约 750（`mode` 混合 `latest/recommend/search/ask`，`dwell_ms` 有分布）+ `user_action` 约 250（点赞/收藏） |
| 冗余计数一致 | 生成后**回写** `article.view_count / like_count / collect_count`，与行为日志汇总一致（否则 UI 与看板会自相矛盾） |

## 2. 安全与幂等

- **只动自己造的数据**：脚本自带 `--reset`，按种子用户名（`demo_user_*` / `bot_*`）与其作者 id 清理，**绝不触碰**既有 12 个用户、17 篇文章、47 条浏览日志
- 默认执行顺序：`--reset`（若存在）→ 插入用户 → 插入文章 → 插入行为 → 回写计数 → 打印核对报告
- 固定随机种子（可复现）：同一命令两次运行生成同样的数据

## 3. 验收标准（验证方实测）

1. 计数达标：用户 +35、文章 +100、行为 +1000（相对既有数据）
2. **一致性**：`article.like_count/collect_count/view_count` 与 `user_action`/`browse_log` 汇总**逐篇一致**
3. **不影响既有数据**：原有 12 用户 / 17 文章 / 47 浏览日志不变（可见文章总数 = 17 + 100）
4. `/admin/stats/overview` 与 SQL 直查一致；`/article/search?keyword=…&timeRange=1d/7d` 有结果（时间窗可演示）
5. 前端首页信息流、推荐/最新、搜索、问答四条路径都能在这些数据上正常展示
6. `--reset` 后库回到执行前的状态（可验证）
