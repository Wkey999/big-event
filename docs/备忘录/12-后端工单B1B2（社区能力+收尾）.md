## A. B1 —— 帖子媒体 + 话题

### A1 表结构

按 `备忘录 11 §3` 原样创建 5 张表（本批先用到 `post_media` / `topic` / `post_topic`）：

| 表 | 必须存在的列 | 必须存在的索引 |
|---|---|---|
| `post_media` | id, article_id, url, media_type, sort_order, width, height, create_time | `idx_article(article_id, sort_order)` |
| `topic` | id, name, post_count, hot_score, status, create_time | `uk_name(name)`、`idx_hot(status, hot_score)` |
| `post_topic` | article_id, topic_id, create_time | 主键 `(article_id, topic_id)`、`idx_topic(topic_id)` |

迁移文件：`sql/migration/005_community_core.sql`。

### A2 接口

| 方法 | 路径 | 请求 | 响应要点 |
|---|---|---|---|
| GET | `/article/{id}/media` | — | `[{id,url,mediaType,sortOrder,width,height}]` 按 `sort_order,id` 升序 |
| PUT | `/article/{id}/media` | `{"media":[{"url":"","mediaType":1,"width":0,"height":0}]}` | 全量替换；**第一条同步写入 `article.cover_img`**；仅作者或管理员 |
| GET | `/topic/list?sort=hot\|new&limit=20` | — | `[{id,name,postCount}]`；`hot` 按 `hot_score DESC, post_count DESC`，`new` 按 `create_time DESC`；仅 `status=1` |
| GET | `/topic/{id}/posts?pageNum&pageSize` | — | 该话题下**已发布**帖子分页（复用列表字段，不含 `content`） |

### A3 实现要点

1. **话题按名字 upsert**：提交 `topicNames:["a","b"]` 时，存在则复用、不存在则创建（`name` ≤30 字、去首尾空白、**一帖最多 5 个**，超出报错）
2. **`topic.post_count` 必须与 `post_topic` 行数一致**：增删帖子的关联时同步维护（同一事务）
3. 发帖/改帖接口扩展：`POST /article/add`、`PUT /article/update` 接受可选 `media[]` 与 `topicNames[]`（**不传时行为与现在完全一致**）
4. 删除/软删帖子时，同时清理该帖的 `post_topic` 关联并回退 `topic.post_count`

## B. B2 —— 评论 + 关注

### B1 表结构

同批建 `comment` 与 `user_follow`（列与索引见 `备忘录 11 §3`）。

### B2 接口

| 方法 | 路径 | 请求 | 说明 |
|---|---|---|---|
| GET | `/article/{id}/comments?pageNum&pageSize` | — | **只分页顶层评论**（`root_id IS NULL`）；每层带 `replyCount` 与前 2 条回复；按 `create_time DESC, id DESC` |
| GET | `/comment/{rootId}/replies?pageNum&pageSize` | — | 某楼层的全部回复（`root_id = ?`），`create_time ASC` |
| POST | `/article/{id}/comment` | `{"content":"","rootId":null,"parentId":null}` | 内容 ≤500 字、非空；返回新评论 |
| DELETE | `/comment/{id}` | — | 仅作者或管理员；**软删**（`deleted=1`） |
| POST/DELETE | `/comment/{id}/like` | — | 幂等；复用 `user_action`（`target_type=2`, `action_type=1`） |
| POST/DELETE | `/follow/{userId}` | — | 幂等；**不能关注自己**；返回 `{followed, followerCount, followeeCount}` |
| GET | `/user/{id}/follow` | — | `{followed:bool, followerCount, followeeCount}` |

### B3 实现要点

1. **两级结构**：顶层评论 `root_id = NULL`；回复必须携带 `rootId`（且该 root 必须属于同一帖）；`parentId` 可选（表示回复某条回复）
2. **计数一致性**（同一事务内维护）：
   - `article.comment_count` = 该帖**未删除**评论总数（含回复）
   - `comment.reply_count` = 该楼层**未删除**回复数（只在 root 上累加）
   - `comment.like_count` = `user_action`（`target_type=2, action_type=1`）行数
3. **可见性**：草稿帖（`state=0`）**不能被评论**，未登录不可评论；已软删评论不出现在列表与计数里
4. **幂等**：重复关注/取关、重复点赞/取消，计数**不得漂移**（用唯一键 + `DuplicateKeyException` 兜底或 `INSERT ... ON DUPLICATE KEY UPDATE`）
5. `@Transactional` 覆盖所有写操作；分页参数夹取（`pageSize ≤ 100`）；排序带 `id` tiebreaker

## D. 验收标准（验证方实测，逐条跑）

1. **迁移**：`005`（与 `004`）重复执行无副作用；列/索引与 §A1/§B1 清单一致
2. **计数一致性**（SQL 直查，必须全为 0 不一致）：
   - `article.comment_count` vs `comment` 未删行数
   - `comment.like_count` vs `user_action(target_type=2,action_type=1)`
   - `comment.reply_count` vs 该楼层未删回复数
   - `topic.post_count` vs `post_topic` 行数
   - `article.cover_img` vs 该帖 `post_media` 首条 URL
3. **幂等**：重复关注/取关 ×2、重复点赞/取消 ×2 → 计数不漂移
4. **关注流**：`GET /feed?mode=following` 只出现**已关注作者**的**已发布**帖子；没有关注时返回空而不是全部
5. **评论结构**：楼中楼归属正确；跨帖回复被拒；删除后计数 -1 且列表不再出现；分页不重不漏
6. **权限**：普通用户删他人评论 → 业务错误；未登录写操作 → 401；草稿帖评论 → 业务错误
7. **回归**：既有 23 个路由 + `/admin` 权限矩阵（401/403/200）+ 搜索（含时间窗）**零变化**；`mvn clean test` 全绿；**零配置空目录可启动**
8. **C1/C2/C3** 逐条验证（含 404 语义与 002/004 迁移状态）
