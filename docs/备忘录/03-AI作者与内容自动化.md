# 备忘录 03：AI 作者账号与内容自动化

## 一句话目标

创建若干 **AI 作者账号**（体育小助手、电竞小助手、AI 资讯小助手…），由定时任务**自动产出/更新**文章，
让站点在无人值守时也有新鲜内容——替代现在"全靠后台手动上传"的模式。

## 现状（代码事实）

1. **没有"机器作者"概念**：`user` 表只有 `role`（0 普通 / 1 管理员）、`status`（0 禁用 / 1 正常）。
   文章作者就是普通账号，`article.user_id` 指向 `user.id`。
2. **所有内容都是人工上传**：`POST /article/add` + `PUT /article/update`，`state` 0 草稿 / 1 已发布。
3. **已有定时任务范式可直接复用**：`task/ProfileRefreshTask.java` + `config/SchedulingConfig`（`@EnableScheduling`，cron `0 0 3 * * ?`）。
4. **频道是共享的、只有管理员能建**（`CategoryServiceImpl#assertAdmin`）：AI 作者发文只能选**已存在**的频道。
5. **封面走 OSS**：`utils/OssUtils`；未配置 OSS 时上传会抛 `对象存储尚未配置` → 自动发文需要封面兜底策略。
6. **推荐链路已就绪**：`mode=recommend`（阶段 C）会按画像权重 × 时间衰减 × 热度重排 → 新内容能被"新鲜度"加权推出去。

## 方案（四步）

### 第 1 步：账号模型

- `user` 增加 `user_type tinyint NOT NULL DEFAULT 0 COMMENT '0-人类 1-机器作者'`（或 `is_bot`），并保留 `role=0`。
  **不要复用 `role=1`**（那是管理员权限，过大且会被 `/admin` 放行）。
- AI 账号示例：`username=bot_sports`、`nickname=体育小助手`、`avatar=...`、简介"自动聚合体育资讯"。
- 登录控制：给 AI 账号设置**不可登录**（新增 `login_enabled tinyint`，而不是用 `status=0`——`status` 语义是"禁用"，会影响作者展示与文章可读性判断）。
- 前台展示：作者名旁显示「AI 助手」标识；作者主页列出该机器人发布的文章。

### 第 2 步：内容流水线

```
选题(频道+时间窗) → 素材(官方RSS/开放API/人工投喂) → LLM 生成(标题/摘要/正文/标签)
   → 质量校验(长度、敏感词、与既有文章去重) → 落库为草稿(state=0)
   → 【可选】人工审核 → 发布(state=1)
```

- 新增审计字段（建议新表 `bot_article_source` 或 `article` 扩列）：`source_url`、`model`、`prompt_version`、`generated_at`、`reviewed_by`、`reviewed_at`。
- **去重**：`source_url` 唯一索引 + 标题相似度检查，避免同一事件反复刷屏。

### 第 3 步：调度与限流

- 新增 `task/BotContentTask`（复用 `@EnableScheduling` 范式），例如每频道每小时最多 N 篇、每日总量上限。
- **全局 kill switch**：`app.bot.enabled=false` 一键停止所有自动发文（配置开关，无需改代码）。
- 失败处理：单篇失败不影响整批；失败原因落库（`bot_task_log`），保留重试次数。

### 第 4 步：后台呈现（依赖备忘录 01 的管理端）

- `/admin` 增加"AI 作者管理"（启停、频率、绑定频道）与**审核队列**（批量通过 / 打回 / 下线）。
- 数据看板：每日产出量、通过率、被举报/下线数。

## 风险与取舍（务必写进设计文档）

| 风险 | 说明 | 建议 |
|---|---|---|
| 合规标识 | 国内对 AI 生成内容有标识要求，且不宜伪装真人 | 作者标注「AI 助手」；文章详情标注"由 AI 生成/整理，仅供参考" |
| 幻觉与事实错误 | 体育/电竞资讯事实性强（比分、转会），LLM 极易编造 | **优先"采集+改写摘要并附来源链接"**，不生成无来源的事实性断言 |
| 版权 | 整篇搬运第三方内容有侵权风险 | 只存**链接 + 摘要 + 自己的评述**；优先用官方 RSS/开放 API |
| 内容质量稀释 | 自动内容刷屏会拉低推荐流质量 | 推荐公式对 `user_type=1` 的文章**降权**；限制单频道占比 |
| 成本 | 每篇 1~3 次调用 | 设每日上限 + 监控；DeepSeek 单价低，但要有"超额熔断" |
| 运营失控 | 无人值守下可能持续产出低质内容 | 初期**必须保留人工审核闸门**；kill switch 随时可停 |

## 验收标准

1. 5 个 AI 账号能按调度**自动产出通过校验的草稿**（不人工干预）。
2. 审核闸门开启时，自动内容**不会**直接进入已发布状态。
3. kill switch 生效后，不再产生任何新内容（且不影响已有文章）。
4. 前台能正确展示「AI 助手」署名与生成标识；作者主页可筛出该机器人文章。
5. 去重生效：同一 `source_url` 不会重复入库；标题高度相似的内容会被拦截。
6. 埋点/推荐回归：自动内容进入推荐流后，`browse_log` 与画像统计不报错、排序正常。
