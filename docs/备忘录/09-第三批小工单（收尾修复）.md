## F1（最重要）404 语义：不存在的路由被吞成「HTTP 200 + 服务器内部错误」

**实测证据**（带合法 token）：
```
GET /no/such/path    -> [HTTP 200] {"code":1,"message":"服务器内部错误","data":null}
GET /article/nosuch  -> [HTTP 200] {"code":1,"message":"服务器内部错误","data":null}
```
**原因**：`config/GlobalExceptionHandler` 的兜底 `@ExceptionHandler(Exception.class)` 把 Spring 的
`NoResourceFoundException`（Spring Boot 3.2+ 对未匹配路径抛出的异常）也接住了。

**为什么必须修**：路径写错时看起来像"服务器炸了"，前端无法区分"接口不存在"与"服务端故障"；
也会把"控制器没注册"这种状态掩盖成 500。

**要求**：
- 在 `GlobalExceptionHandler` 中**单独**处理 `NoResourceFoundException` 与 `NoHandlerFoundException`：
  返回 **HTTP 404** + `{"code":404,"message":"接口不存在","data":null}`
- **不要回归**：已存在路由的**业务错误**必须仍是 **HTTP 200 + `code≠0`**（例如参数校验失败、
  「智能问答未启用」、权限相关业务提示）——这是两件不同的事
- 未登录访问不存在路径时，仍应由 `JwtInterceptor` 先返回 **401**（拦截器优先，保持现状）
- 新增测试：① 已登录访问不存在路径 → 404 + code=404；② 参数校验失败仍是 200 + code≠0（防回归）
