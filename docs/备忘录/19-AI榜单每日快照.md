# AI 榜单每日快照（本地实现，尚未部署）

## 上线顺序

1. 先备份目标 MySQL 数据库，确认当前库已完成 `001`–`012`；**不要**重跑会覆盖业务数据的 `sql/big_event_init.sql`。
2. 执行增量迁移 `sql/migration/013_leaderboard_snapshots.sql`。它只新增三张表，可在 MySQL 5.7/8.0 重复执行；不会改动现有文章、用户或资讯表。上线前仍需在目标 MySQL 版本上实际演练。
3. 部署新后端并验证 `GET /leaderboard/models?dimension=text`。没有快照时返回 `status=unavailable` 和空 `items`，不以测试数据填充。
4. 确认服务器可访问 `datasets-server.huggingface.co:443`，然后通过私有生产环境配置设置 `APP_LEADERBOARD_SYNC_ENABLED=true` 并重启服务。不要把代理凭据或其他密钥写进仓库。

本次仅改本地后端源码；上述步骤尚未在业务库或服务器执行。

## 同步与保留

- 五个维度仍读 Arena Leaderboard Dataset 的 `latest`，只取 `overall` 且排名 1–100 的真实行。对话、建站、搜索、视觉使用 `rating`（Arena Score）；Agent 使用 `score`（IPS 分数）。来源与许可证见 [Arena 数据集](https://huggingface.co/datasets/lmarena-ai/leaderboard-dataset)。`sourceDate` 取本次收录行中最近的有效 `leaderboard_publish_date`；它不是模型发布日期。
- 默认每天 `Asia/Shanghai` 04:20 同步；可分别配置 `APP_LEADERBOARD_SYNC_CRON`（Spring cron）和 `APP_LEADERBOARD_TIME_ZONE`（IANA 时区）。默认关闭，迁移完成后再开启。首次开启时，重试检查任务会在启动后约 1 分钟为无记录维度尝试初始化。
- 每维度独立，默认连接超时 5 秒、读取超时 12 秒。失败后至少间隔 5 分钟、当天最多 3 次尝试；访客 GET 只读 MySQL，不触发外网请求。同一进程的并发任务通过维度级锁跳过重复调用；写入时数据库行锁串行化状态更新。
- 成功时，在一个事务中保存快照、模型行和成功状态。同一同步日、与最近成功快照内容完全相同的结果只更新最后成功检查时间；跨日再次成功即便内容相同，也保留新的一份日档。上游同一天确实更新了排名或分数时，另存新快照。失败只更新同步状态，不移动最近成功快照指针，也不计算新排名变化。
- 历史快照暂不自动删除，避免误删论文分析所需数据。最大约 5 维 × 100 行 × 365 日，即每年约 18.25 万行模型记录（同日上游多次变更会增加）；长期使用需监控磁盘与备份体积，再确定归档周期。

## 接口契约

仍为 `GET /leaderboard/models?dimension=text|webdev|search|vision|agent`，保留原有 `dimension`、`label`、`metric`、`sourceUrl`、`sourceDate`、`checkedAt`、`status`、`items` 和模型的 `rank`、`name`、`organization`、`license`、`score`、`publishedDate`。已有前端可以继续读取这些字段，不需要本次修改。

新增榜单字段：

| 字段 | 含义 |
| --- | --- |
| `snapshotId` | 本站保存的成功快照编号；无快照为 `null`。 |
| `snapshotSyncedAt` | 当前快照首次保存时间，UTC ISO-8601；与再次检查成功的时间可不同。 |
| `lastSuccessfulSyncAt` | 最近一次成功读取并确认真实上游数据的时间，UTC ISO-8601；旧字段 `checkedAt` 与之相同。 |
| `lastAttemptAt` | 最近一次尝试时间，UTC ISO-8601。 |
| `lastAttemptStatus` | `never`、`success`、`failed`。 |
| `syncSummary` | 不包含密钥或原始响应内容的状态摘要。 |
| `status` | `available`=最近一次尝试成功；`stale`=最新尝试失败但有成功快照；`unavailable`=尚无成功快照。 |

新增模型字段：`newlyListed`、`previousRank`、`rankChange`、`rankTrend`。`rankChange = previousRank - rank`：正数表示上升，负数表示下降，0 表示不变；`rankTrend` 为 `up/down/same/new`，首次基线为 `null`。首次成功快照的所有 `newlyListed=false`；以后只与**同一维度最近一次成功快照**按 Arena 的 `model_name` 精确匹配。名称改变会被当成不同模型；退出本站前 100 范围后再次进入会再次标为新上榜。“新上榜”只指进入本站收录范围，不代表模型刚发布。

无历史快照时的实际响应结构示例（不含任何伪造的模型或分数）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "dimension": "text",
    "label": "对话",
    "metric": "Arena Score",
    "sourceUrl": "https://huggingface.co/datasets/lmarena-ai/leaderboard-dataset",
    "sourceDate": null,
    "checkedAt": null,
    "status": "unavailable",
    "items": [],
    "snapshotId": null,
    "snapshotSyncedAt": null,
    "lastSuccessfulSyncAt": null,
    "lastAttemptAt": null,
    "lastAttemptStatus": "never",
    "syncSummary": "尚无同步记录"
  }
}
```

配套前端已在本地改为展示“新进入前 100”、排名升降、上游榜单日期、本站成功同步时间与失败后的历史快照提示；“数据最多缓存 2 小时”的旧文案已移除。前后端改动仍未提交或部署；上线时应一起更新，避免旧前端继续使用过时文案。

## 验证边界

单元测试覆盖解析、Agent 指标隔离、首次基线、排名变化、同日去重、跨日归档、单维度失败、无历史与历史降级，并用新的存储对象读取模拟进程重启。2026-10-29 的后端测试及前端构建通过；这些测试不使用真实 MySQL 或 Redis。迁移与 MyBatis 语句仍需在**明确隔离的 MySQL 5.7 测试库**演练；本轮未向业务库写入测试数据。没有验证线上出站网络或真实 Arena 当日响应。由于读取端点当前只请求首 100 行并再筛选 `overall`，收录范围可能不是官方完整前 100，后续应核验上游分页与过滤能力。
