## 建议优先级与理由

1. **01 前后台分离**——现在管理能力与消费接口共用 `/article/list`，管理员纵览靠 `isAdmin() ? null : userId` 隐式分叉；越晚改，前端要跟着改的点越多。
2. **02 AI 搜索**——后端一半已具备（`POST /article/ask` + 只读工具 + references 溯源），增量最小、演示效果最好；关键是补"普通搜索"和"时间维度"。
3. **03 AI 作者自动化**——最有"自动化"故事性，但涉及合规/质量/成本，且需要一个后台审核入口，所以放最后。
