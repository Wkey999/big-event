# RAG 索引可靠性与评测修正

实施日期：2026-10-31。本轮修改本地后端仓库，以及前端文档助手页的默认策略和费用/维度提示；没有操作业务数据库、提交或部署服务器。初期实现与测试未调用付费模型，后续由用户单独授权了一次云端小量验证，结果见文末。

## 问题与处理

1. 原来文档使用远程 Embedding 后，问题编码失败会降级为本地特征编码，再搜索远程索引。即使维度相同也不在同一空间。现在向量与混合检索固定使用建索引时的不可变配置；失败返回明确 503，用户可改选 BM25。Java 网关在检索成功后才创建聊天客户端并预留聊天额度。已发生的 Embedding 请求可能仍由供应商计费。
2. 原缓存只区分 remote/local。现在文档、模型、服务地址、凭据指纹、维度配置与编码版本均参与 SHA-256 索引身份；本地词簇改变会使旧索引失效。远程模型如果在同一名称下更换权重，仍需由运维清理缓存或更换模型标识；无法自动推断供应商内部版本变化。
3. 原磁盘只有 `.faiss` 写入，没有恢复。新增独立 `app/vector_index.py`，以单文件校验包保存元信息与 float32 矩阵，加载前校验大小、维度、数量、内容摘要及有限值，再恢复 FAISS flat 索引。无需反序列化任意对象，也不加载旧 `.faiss`。损坏重建，写盘失败回退内存，不掩盖远程服务失败。
4. 内存 LRU 64 个；磁盘每次成功写入后保留最近写入的 64 个合法命名文件。进程内建索引串行以防重复编码，搜索不持有建索引锁。原子替换防止部分写入；多进程可能重复编码但不会共享半份缓存。缓存目录应由服务账号独占，向量也属于私有数据。
5. 远程响应校验索引顺序、数量、非空有限向量、维度和查询维度一致性；超时、429、异常响应只向用户返回固定提示，不返回供应商正文或密钥。
6. 评测原来使用 260/30 特殊分块，且无答案题使用线上没有的额外阈值，导致拒答指标虚高。现在与服务一致使用 700/80 分块及正分返回口径；将错误命名的 Recall@3 修正为 Hit@3，删除预设最优结论，保留失败样例。
7. 远程向量不再要求命中离线手写同义词表；使用可配置的向量分数阈值（`EMBEDDING_MIN_SCORE`，原型默认 0.35），避免真正的语义命中被字面规则误删。该阈值仍需按所选模型在独立保留集校准。
8. 前端默认改为与后端一致的 BM25，移除未经独立评测支持的混合检索“推荐”、固定 512 维和“0 消耗”提示；摘录与拒答不调用聊天模型，但远程 Embedding 本身可能计费。

## 实际验证

- Python 测试覆盖同配置复用、配置隔离、无静默降级、超时和异常响应、查询维度变化、损坏与截断缓存、写盘失败、内存/磁盘容量、同文档并发建索引、独立进程恢复以及评测拒答口径。
- Java 测试以本机 HTTP stub 返回检索 503，验证没有创建聊天模型客户端或扣减平台聊天额度；继续验证正常问答、引用编号过滤与功能开关。
- 离线重新生成 30 题报告，未调用远程 Embedding/聊天模型。默认编码仍是离线词簇与特征哈希，不是预训练语义模型；题目与词簇主题有重合，不能用该报告宣称泛化准确率。真实模型和线上环境未验收。
- 实际结果：Python 23 项测试通过；Java 文档助手与功能开关 11 项测试通过；前端生产构建与分包检查通过。未连接业务数据库；没有做真实供应商调用、完整浏览器联调或 Linux 服务部署验收。Java 首次编译出现本地资源关闭异常，重新执行后构建与全部目标测试通过。

## 配置与运行

本机启动见 `document-assistant/README.md`。启用 `VECTOR_CACHE_DIR` 后，重启并重新提交相同文档会恢复索引，无需重新编码文档；没有原文数据库和用户文档列表。服务模板新增 `/etc/boom/assistant.env` 私有配置与 `/var/lib/boom-assistant` 状态目录；模板本轮未部署。

## 下一步实施顺序

1. 选择一种 Embedding 模型及明确版本，在授权的预算内小规模验证真实语义检索；建立与当前词簇和开发题目分离的保留集，记录命中、误召回、拒答、引用支持度、冷启动/热查询与端到端耗时。
2. 再加入完整文档知识库：Java 管理文档归属、版本及索引状态，Python 构建索引；设计上传、索引中、可用、失败、删除状态，并让更新/删除可幂等重试。查询前由 Java 校验文档所有权，不能直接把全局索引向用户开放。
3. 最后接前端文档列表、索引进度和引用定位，基于独立测试集与真实文档验收。当前 LangChain 只负责递归切块，不能把整个链路称为 LangChain Agent 编排。

## 同日追加：百炼云端接入准备

用户已选择先用云端 Embedding，目标为北京地域 `text-embedding-v4`。已加入忽略提交的 `.env.local` 与可提交模板，`run_cloud.py --check` 做无网络配置检查、`--probe` 用两句合成文本做显式小量连接验证、不带参数启动 Python 服务。启动器不会自动调用探测，不打印 Key，也不修改系统环境变量。

远程请求已实现每批最多 10 条，按输入顺序合并批次，跨批维度一致；所有批次成功后才建索引，失败不缓存半份结果、不自动重试。按单次编码预算在批次边界停止额外请求，避免长文不断重试消耗；HTTP 同步超时不构成硬实时保证，已经成功的批次仍可能计费。

追加后 Python 总计 32 项测试通过，涵盖 23 条输入拆成 10/10/3、批内乱序、第二批失败、跨批维度变化、预算耗尽、私有配置校验及 `--check` 不联网。

用户随后在本机填写 Key 并明确授权小量验证。执行一次 `run_cloud.py --probe`：向北京地域 `text-embedding-v4` 提交两句合成文本，成功返回 2 条、每条 1024 维的合法归一化向量；没有调用聊天模型，没有追加语义质量或 RAG 生成请求。该结果仅证明接口连通与响应契约，不证明检索效果；未查询供应商实际 Token 用量或账单，费用以其控制台为准。Key 始终只保存在忽略提交的私有配置中。

随后用 `run_cloud.py` 启动本机 Python 服务，`GET http://127.0.0.1:8001/health` 返回 `status=ok`、`embedding_mode=remote-openai`。健康检查不调用模型；本次没有通过浏览器发起额外付费检索，也未做 Java/前端整链路验收。运行日志位于仓库忽略目录 `logs/document-assistant-cloud.stdout.log` 与 `logs/document-assistant-cloud.stderr.log`。

## 实现参考

FAISS 的内积索引用于余弦相似度时需对文档和问题向量归一化，见 [FAISS 距离说明](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances)。其通用索引反序列化不负责验证输入可信性，见 [FAISS 索引 I/O 说明](https://github.com/facebookresearch/faiss/wiki/Index-IO,-cloning-and-hyper-parameter-tuning)。本次缓存保存经校验的向量矩阵，再建立 flat 索引，不加载外部上传的 FAISS 二进制文件。
