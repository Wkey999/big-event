## B. 普通搜索（后端，已完成）

### B1 接口契约

```
GET /article/search
  keyword    必填（`@NotBlank`），≤100 字符
  categoryId 可选
  authorId   可选
  timeRange  可选，白名单 all|1d|7d|30d（缺省 all；1d表示滚动24小时；非法值明确报错）
  orderBy    可选，latest（缺省）| popular（按 view+like+collect）
  pageNum    缺省 1（夹到 1–100000）
  pageSize   缺省 10（夹到 ≤100）

→ { code:0, data:{ total, items:[{
      id, title, summary, coverImg, categoryName, authorNickname, publishedAt,
       likeCount, collectCount, viewCount,
      hitField: "title"|"summary"|null,
      hitSnippet: "含关键词的纯文本片段（≤60字，无 HTML）"
   }] } }
```

硬性要求：
- **只返回已发布**（`state=1 AND deleted=0`），**永不返回 `content`**
- **服务端不返回 HTML 高亮**，只返回 ≤60 字纯文本 `hitSnippet` 和 `hitField`；前端用文本节点分段高亮（避免引入新的 XSS 面）
- 结果按 `orderBy` 排序，`latest` 用 `create_time DESC, id DESC`（保持与现有列表一致的 tiebreaker）
- 登录后才能搜索（沿用现有 JWT 拦截器，不额外放行）

### B2 日志（`search_log`）✅

- 每次搜索**成功返回后**写入：`user_id, keyword, category_id, time_range, result_count, elapsed_ms`
- 照 `AskLogService` 的模式：**best-effort**，写失败只 `warn`，**绝不影响搜索响应**；keyword 截断 100
- 未登录不会走到这里（接口需登录）

### B3 测试 ✅

- 只返回已发布（构造一条草稿断言不出现）
- `timeRange=1d` 时 query 条件包含 `createdAfter`（可用 Mockito 断言参数）
- 非法 `timeRange` → `BusinessException`
- `%` `_` 被转义后不再命中全部（A2 的回归测试）

3. ✅ **AI 搜索时效**（DSH 实测，2026-10-13）：「最近24小时内有哪些AI相关的新闻」→ 模型回答“最近24小时内没有检索到 AI 相关的已发布文章……”且 **0 引用**（`ask_log.id=6`、elapsed=1859ms、success=1）→ **窗口内无结果时明确说明、未拿旧文充数**；「有没有和篮球有关的已发布文章」→ 返回真实引用（`ask_log.id=5`、refs=1、elapsed=2089ms）。受控时间窗实验（同关键词 all=2 / 30d=2 / 7d=1 / 1d=1）另证 SQL 过滤正确。

## F. 安全与边界（必须遵守）

- 服务端**不返回 HTML**（高亮在前端做），避免新的 XSS 面
- 搜索日志不落敏感内容；keyword 截断 100；沿用 `AskLogService` 的脱敏思路（可选）
- `timeRange` / `orderBy` **白名单校验**，非法值明确报错
- `orderBy` 全链路统一为 `latest|popular`，不混用 `hot/hottest`
- 搜索接口**需登录**，不做匿名开放
- **不引入新中间件**（不向量库、不 ES）—— 本批只用 MySQL 的 `LIKE` + 时间条件
- 沿用"密钥外置"约定：不得把任何 key 写进仓库
