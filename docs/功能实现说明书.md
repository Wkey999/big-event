# 《BOOM！大事件》功能实现说明书

> 版本：v1.0（2026-09-05）· 状态：**功能冻结，进入收尾阶段**
> 配套仓库：后端 [big-event](https://github.com/Wkey999/big-event) · 前端 [big-event-web](https://github.com/Wkey999/big-event-web)

## 1. 系统概述

一个**作者视角的内容社区管理系统**：注册登录后，作者管理自己的文章分类与文章（富文本 + 封面图），首页以瀑布流信息流浏览自己的已发布内容。

```
浏览器（Vue 3 SPA, :5173）
   │  /api 前缀，Vite dev 代理 rewrite
   ▼
Spring Boot 3.4.1（:8080，JWT 拦截器 → Controller → Service → MyBatis Mapper）
   ├── MySQL 5.7（big_event 库，8 张表）
   └── 阿里云 OSS（图片对象存储，公网读）
```

**关键定位澄清**：所有数据按 `userId` 隔离，系统内没有"公开信息流"——每个账号只能看到自己发布的内容。这是一个**单角色（作者/管理员）系统**，不是多用户社区。

## 2. 核心业务流程

| 流程 | 路径 |
|---|---|
| 账号 | 注册（前后端双重校验）→ 登录拿 JWT → 后续请求 `Authorization: Bearer` → 改资料/改密（改密后强制重登） |
| 内容生产 | 建分类（名称/排序）→ 发文章（标题/分类/摘要/封面上传/富文本正文/存草稿或发布）→ 编辑/删除 |
| 内容消费 | 首页瀑布流（仅已发布）→ 触底无限加载 → 点开预览全文（不虚增浏览量） |

## 3. 功能清单（已实现）

### 3.1 用户模块
- [x] 注册：用户名 `^[a-zA-Z0-9]{3,20}$`、密码 `^\S{6,20}$`、确认密码一致性（前端规则与后端 DTO 逐条对齐）
- [x] 登录：JWT（jjwt 0.12.6）签发，拦截器统一鉴权，白名单仅注册/登录
- [x] 个人信息查询/更新（昵称、邮箱、头像；**局部更新安全**，缺省字段不覆盖）
- [x] 修改密码：DTO 校验（旧密码比对 BCrypt/编码器，新密码规则同注册），成功即失效当前会话
- [x] 头像/图片上传：`POST /user/upload` 直传 OSS 返回公网 URL

### 3.2 分类模块（按用户隔离）
- [x] 列表（按 `sort_order` 排序）/ 新增 / 编辑 / 删除（确认框）
- [x] 名称规则 `^\S{1,20}$`；重名双层防御：服务层预检（含编辑时排除自身）+ `DuplicateKeyException` 兜底

### 3.3 文章模块（按用户隔离）
- [x] 分页列表：分类 + 状态（草稿/已发布）组合筛选，`PageBean`（count + LIMIT）
- [x] 新增/编辑：`ArticleAddDTO` / `ArticleUpdateDTO` 全字段校验，状态 `@InValues(0,1)` 自定义注解
- [x] 详情（浏览量 +1，前端编辑预填刻意**不走**详情接口避免虚增）
- [x] 删除（软删除）；删掉当页最后一条自动回上一页
- [x] 归属校验（IDOR 防护）：改/删他人资源、挂他人/不存在/已软删分类，统一一条模糊错误拒绝，写前校验不留部分写

### 3.4 前端页面（7 个视图）
- [x] 登录页、注册页（玻璃卡 + 主题色链接互跳）
- [x] 主布局：侧边栏胶囊菜单（4 项，刷新/直达深层路由高亮正确）+ 头部头像下拉（退出登录）
- [x] 首页信息流：多列瀑布流（不依赖布局库：确定性封面比例 + 贪心列分配，追加不跳位）、IntersectionObserver 无限滚动（预取余量 200px）、骨架首屏、空态引导、失败重试
- [x] 分类管理页、文章管理页（筛选 + 分页 + 大弹窗表单 + wangeditor 富文本 + 封面上传预览/移除）
- [x] 个人中心页（el-tabs 基本资料 / 修改密码）
- [x] 整站主题层：`src/styles/theme.css` 单一来源（雾面冷灰蓝 + 玻璃拟态；瀑布流卡片用伪玻璃保帧率）

## 4. 接口一览（16 个）

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/user/register` | 注册 | 免 |
| POST | `/user/login` | 登录，返回 token | 免 |
| GET | `/user/userInfo` | 当前用户信息（不含密码） | Bearer |
| PUT | `/user/update` | 更新资料（局部安全） | Bearer |
| PUT | `/user/updatePwd` | 改密（下划线键 `old_pwd`/`new_pwd`） | Bearer |
| POST | `/user/upload` | 图片上传 OSS，返回 URL | Bearer |
| GET | `/category/list` | 我的分类（sort_order 序） | Bearer |
| POST | `/category/add` | 新增 | Bearer |
| GET | `/category/detail/{id}` | 详情 | Bearer |
| PUT | `/category/update` | 编辑 | Bearer |
| DELETE | `/category/delete/{id}` | 软删 | Bearer |
| GET | `/article/list` | 分页筛选（`state` 传中文「草稿/已发布」） | Bearer |
| POST | `/article/add` | 新增 | Bearer |
| GET | `/article/detail/{id}` | 详情，浏览量 +1 | Bearer |
| PUT | `/article/update` | 全量更新（前端整对象提交） | Bearer |
| DELETE | `/article/delete/{id}` | 软删 | Bearer |

统一响应 `{code, msg, data}`；异常经 `GlobalExceptionHandler` 收敛（校验消息取首个字段错误）。

## 5. 数据模型（8 表）

**在用**：`user`、`category`、`article`（软删 `deleted`、冗余 `view_count`、状态 0/1）
**已建未接入**（课程预留）：`tag`、`article_tag`、`comment`、`user_action`（多态）、`file_record`
设计要点：无物理外键、软删除、计数冗余；`category_name` 库 30 字符但接口收紧到 20。

## 6. 非功能实现

- **密钥卫生**：JWT 密钥/DB 密码/OSS AK 全在 gitignored `application-secret.yml`、`application-oss.yml`，全提交历史零泄漏（已扫描核验）
- **多环境**：dev(8080)/prod(9090) profile 拆分，`spring.config.import` 注入
- **前端契约**：axios 拦截器统一注 token、`code!==0` 弹错、401 清 token 跳登录；中文经代理→后端 UTF-8 链路已验证
- **可回溯**：双仓库 git 化，提交历史完整

## 7. 已知边界与未实现（收尾核对清单）

| 项 | 现状 | 建议 |
|---|---|---|
| 异常信息泄漏 | `GlobalExceptionHandler` 把 `e.getMessage()` 回传客户端，**仓库已公开** | 收尾必修：记日志 + 返回笼统文案 |
| 分类删除连带 | 删分类不查在架文章 → 孤儿文章改不动 | 收尾必修：拒绝删除或级联 |
| 无公开 C 端 | 访客必须注册，只能看自己的内容 | 定位如此，不改（见 §1 澄清） |
| 评论/点赞/标签 | 表已建，代码未接 | 不再做（超出收尾范围） |
| 浏览量防刷 | detail 一次 +1，无去重 | 不再做 |
| token 吊销 | JWT 无状态，改密只清前端 | 已知限制，文档如实写 |
| 测试/CI/部署 | 无单测、无 CI、无 Docker | 见 README 阶段 4，按需 |
| 演示数据 | 24 篇霓虹封面与灰蓝主题不搭 | 可重做低饱和封面或清空 |
