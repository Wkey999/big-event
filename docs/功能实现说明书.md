# 《BOOM！大事件》功能实现说明书

> 版本：v1.1（2026-09-06）· 权限模型：**共享频道制**（v1.0 的「按 userId 隔离」已于 2026-09-06 废弃，见 §1）
> 配套仓库：后端 [big-event](https://github.com/Wkey999/big-event) · 前端 [big-event-web](https://github.com/Wkey999/big-event-web)

## 1. 系统概述

一个**共享频道制的内容社区系统**：登录用户在首页以瀑布流信息流浏览全站已发布文章；分类是全站「频道」，仅管理员（`role=1`）可增改删；作者管理自己的文章（富文本 + 封面图），管理员可管理全站文章。

```
浏览器（Vue 3 SPA, :5173）
   │  /api 前缀，Vite dev 代理 rewrite
   ▼
Spring Boot 3.4.1（:8080，JWT 拦截器 → Controller → Service → MyBatis Mapper）
   ├── MySQL 5.7（big_event 库，8 张表）
   └── 阿里云 OSS（图片对象存储，公网读）
```

**关键定位澄清**：信息流在**登录用户间共享**——已发布文章（`state=1`）对所有登录用户可见，草稿仅作者本人与管理员可见；仍无匿名公开 C 端（访客必须先注册登录）。权限上是**双角色系统**：普通用户可发文并管理自己的内容，管理员（`user.role=1`）额外管理频道、并可改删任意文章；角色判定每次请求查库，不信任 token 里的旧信息。

## 2. 核心业务流程

| 流程 | 路径 |
|---|---|
| 账号 | 注册（前后端双重校验）→ 登录拿 JWT → 后续请求 `Authorization: Bearer` → 改资料/改密（改密后强制重登） |
| 内容生产 | 建频道（仅管理员：名称/排序）→ 发文章（标题/分类/摘要/封面上传/富文本正文/存草稿或发布）→ 编辑/删除（作者或管理员） |
| 内容消费 | 首页瀑布流（全站已发布）→ 触底无限加载 → 点开预览全文（不虚增浏览量） |

## 3. 功能清单（已实现）

### 3.1 用户模块
- [x] 注册：用户名 `^[a-zA-Z0-9]{3,20}$`、密码 `^\S{6,20}$`、确认密码一致性（前端规则与后端 DTO 逐条对齐）
- [x] 登录：JWT（jjwt 0.12.6）签发，拦截器统一鉴权，白名单仅注册/登录
- [x] 个人信息查询/更新（昵称、邮箱、头像；**局部更新安全**，缺省字段不覆盖）
- [x] 修改密码：DTO 校验（旧密码比对 BCrypt/编码器，新密码规则同注册），成功即失效当前会话
- [x] 头像/图片上传：`POST /user/upload` 直传 OSS 返回公网 URL

### 3.2 分类模块（全站频道，管理员管理）
- [x] 列表（全站频道，按 `sort_order` 排序）/ 新增 / 编辑 / 删除（确认框）；三个写操作需 `role=1`，普通用户被拒「需要管理员权限」
- [x] 名称规则 `^\S{1,20}$`；全站重名双层防御：服务层预检（含编辑时排除自身）+ `DuplicateKeyException` 兜底
- [x] 删除保护：频道名下仍有未删除文章时拒绝软删

### 3.3 文章模块（已发布全站共享，草稿私有）
- [x] 分页列表：已发布文章全站可见，草稿仅作者与管理员可见；分类 + 状态（草稿/已发布）组合筛选，`PageBean`（count + LIMIT）；列表 LEFT JOIN user 返回作者昵称/头像供信息流展示
- [x] 新增/编辑：`ArticleAddDTO` / `ArticleUpdateDTO` 全字段校验，状态 `@InValues(0,1)` 自定义注解
- [x] 详情（浏览量 +1，前端编辑预填刻意**不走**详情接口避免虚增）
- [x] 删除（软删除）；删掉当页最后一条自动回上一页
- [x] 权限校验：改/删限作者本人或管理员；`categoryId` 不存在/已软删统一一条模糊错误拒绝，写前校验不留部分写

### 3.4 前端页面（7 个视图）
- [x] 登录页、注册页（玻璃卡 + 主题色链接互跳）
- [x] 主布局：侧边栏胶囊菜单（4 项，刷新/直达深层路由高亮正确）+ 头部头像下拉（退出登录）
- [x] 首页信息流：多列瀑布流（不依赖布局库：确定性封面比例 + 贪心列分配，追加不跳位）、IntersectionObserver 无限滚动（预取余量 200px）、骨架首屏、空态引导、失败重试
- [x] 分类管理页、文章管理页（筛选 + 分页 + 大弹窗表单 + wangeditor 富文本 + 封面上传预览/移除）
- [x] 个人中心页（el-tabs 基本资料 / 修改密码）
- [x] 整站主题层：`src/styles/theme.css` 单一来源（雾面冷灰蓝 + 玻璃拟态；瀑布流卡片用伪玻璃保帧率）

## 4. 接口一览（16 个）

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/user/register` | 注册 | 免 |
| POST | `/user/login` | 登录，返回 token | 免 |
| GET | `/user/userInfo` | 当前用户信息（不含密码） | Bearer |
| PUT | `/user/update` | 更新资料（局部安全） | Bearer |
| PUT | `/user/updatePwd` | 改密（下划线键 `old_pwd`/`new_pwd`） | Bearer |
| POST | `/user/upload` | 图片上传 OSS，返回 URL | Bearer |
| GET | `/category/list` | 全站频道（sort_order 序） | Bearer |
| POST | `/category/add` | 新增 | Bearer（管理员） |
| GET | `/category/detail/{id}` | 详情 | Bearer |
| PUT | `/category/update` | 编辑 | Bearer（管理员） |
| DELETE | `/category/delete/{id}` | 软删；名下仍有在架文章则拒绝 | Bearer（管理员） |
| GET | `/article/list` | 分页筛选（`state` 传中文「草稿/已发布」）；已发布全站可见 + 本人/管理员草稿 | Bearer |
| POST | `/article/add` | 新增 | Bearer |
| GET | `/article/detail/{id}` | 详情，浏览量 +1 | Bearer |
| PUT | `/article/update` | 全量更新（前端整对象提交） | Bearer（作者或管理员） |
| DELETE | `/article/delete/{id}` | 软删 | Bearer（作者或管理员） |

管理员 = `user.role=1`；角色与归属判定每次请求查库，旧 token 不携带权限缓存。

统一响应 `{code, message, data}`（`code` 0 成功 / 1 失败）；异常经 `GlobalExceptionHandler` 收敛：参数校验取首个字段错误，业务提示（裸 `RuntimeException`）原样回传给前端展示，其余异常只回笼统「服务器内部错误」并把堆栈写进日志。

## 5. 数据模型（8 表）

**在用**：`user`（`role` 0 普通 / 1 管理员）、`category`、`article`（软删 `deleted`、冗余 `view_count`、状态 0/1）
**已建未接入**（课程预留）：`tag`、`article_tag`、`comment`、`user_action`（多态）、`file_record`
设计要点：无物理外键、软删除、计数冗余；`category_name` 库 30 字符但接口收紧到 20。

## 6. 非功能实现

- **密钥卫生**：JWT 密钥/DB 密码/OSS AK 全在 gitignored `application-secret.yml`、`application-oss.yml`，全提交历史零泄漏（已扫描核验）
- **多环境**：dev(8080)/prod(9090) profile 拆分，`spring.config.import` 注入
- **前端契约**：axios 拦截器统一注 token、`code!==0` 弹错、401 清 token 跳登录；中文经代理→后端 UTF-8 链路已验证
- **可回溯**：双仓库 git 化，提交历史完整

## 7. 已知边界与未实现（收尾核对清单）

原列两项「收尾必修」已完成，移出本表：
- **异常信息泄漏** → `GlobalExceptionHandler` 改为 `log.error` 记堆栈 + 返回笼统「服务器内部错误」；业务提示只对「裸」`RuntimeException` 开绿灯，框架异常子类（`DataAccessException` 等）不再回传原文。
- **分类删除连带** → `CategoryServiceImpl.delete` 在管理员权限与存在性校验后统计该分类名下未删文章，`count > 0` 时抛「该分类下仍有文章，请先删除或转移文章」。

| 项 | 现状 | 建议 |
|---|---|---|
| 无匿名 C 端 | 信息流需登录，已发布内容全站共享 | 定位如此，不改（见 §1 澄清） |
| 评论/点赞/标签 | 表已建，代码未接 | 不再做（超出收尾范围） |
| 浏览量防刷 | detail 一次 +1，无去重 | 不再做 |
| token 吊销 | JWT 无状态，改密只清前端 | 已知限制，文档如实写 |
| 测试/CI/部署 | 无单测、无 CI、无 Docker | 见 README 阶段 4，按需 |
| 演示数据 | 2026-09-06 已清洗：25 篇占位文软删，保留 17 篇全部换低饱和封面 | 已完成，测试账号清理见 README 阶段 0 |
